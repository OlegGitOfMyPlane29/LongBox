# challenge100days

Минималистичное full-stack приложение для 100-дневных испытаний с пиксельной эстетикой в стиле Minecraft/Unturned.

```text

└─ README.md
```

## Функциональность

- JWT-аутентификация (email + пароль), роли `user` и `admin`.
- Пользователь создает испытание, указывает до 3 привычек и отмечает ежедневный результат.
- При 100 успехах подряд: `Золотой кубок`.
- При любом провале: `Медный кубок`.
- Комментарии к дню и итоговый комментарий (до 300 символов).
- Общая лента испытаний всех участников.
- UI полностью на русском языке.

## Быстрый старт (Windows 10)

1. Скопируйте `.env.example` в `.env` и заполните значения.
2. Убедитесь, что PostgreSQL запущен и база `challenge100days` создана.
3. В корне проекта запустите:

```bat
run.bat
```

Скрипт создаст `.venv`, установит backend-зависимости, применит миграции Alembic, запустит backend и frontend в отдельных окнах и откроет браузер.

### Запуск через ярлык `zapusk` (Node.js)

Используйте:

```bat
zapusk.bat
```

Что делает `zapusk`:
- проверяет наличие Node.js, npm и Python;
- подготавливает `.venv`, устанавливает зависимости backend/frontend;
- применяет миграции Alembic;
- запускает backend и frontend в отдельных окнах;
- открывает браузер на `http://localhost:5173`.

Запуск сервисов выполняется на `0.0.0.0`, а открытие идет через `localhost` — это стабильно и с VPN, и без VPN.
Если PostgreSQL недоступен, `zapusk` автоматически переключается на локальную SQLite базу `backend/challenge100days.db`, чтобы проект все равно стартовал для проверки.

### Запуск без окна-обертки (`zapusk.vbs`)

Если нужен максимально "тихий" старт, используйте:

```text
zapusk.vbs
```

Этот файл работает как удобный двойной клик-ярлык и открывает консоль запуска `zapusk.bat`, чтобы был виден прогресс и возможные ошибки.

Проверка окружения через VBS:

```text
zapusk.vbs check
```

## Миграции базы данных

```bash
cd backend
alembic upgrade head
```

Образ в корневом `Dockerfile` под Timeweb Apps **не запускает Alembic при старте** (иначе healthcheck не успевает дождаться порта 8080). Перед первым деплоем или после новых миграций выполните `alembic upgrade head` с компьютера (или CI), где доступна та же `DATABASE_URL`, что у приложения в облаке. В переменных Timeweb при необходимости явно задайте **`PORT=8080`**, чтобы совпадал с проверкой здоровья платформы (см. `backend/docker-entrypoint.sh`).

**Важно для `DATABASE_URL`:** символ **`@` в пароле** в URI воспринимается как разделитель «логин:пароль» и «хост». Если пароль содержит `@`, `&`, `>` и т.п., их нужно **URL-кодировать** (например `@` → `%40`, `&` → `%26`, `>` → `%3E`), иначе хост «ломается» и в логах появится ошибка вида `could not translate host name "...@192.168.0.4"`. Проще всего собрать строку в Python: `urllib.parse.quote_plus(пароль)` для части после первого двоеточия. **Timeweb и похожие панели** иногда пересохраняют или показывают строку «в читаемом виде», ломая `%`-кодирование; надёжный обход — **не использовать одну строку**: задать **`DB_HOST`**, **`DB_USER`**, **`DB_PASSWORD`**, **`DB_NAME`** (при необходимости **`DB_PORT`**, **`DB_SCHEME`**) и **очистить или не задавать `DATABASE_URL`** — приложение само соберёт URL (см. `backend/app/config.py`).

**Timeweb Apps (Dockerfile):** поле **«Команда запуска» / custom command** должно быть **пустым**. Запуск задаётся `ENTRYPOINT` → `docker-entrypoint.sh` (**uvicorn за loopback + socat** на `PORT` с dual-stack для healthcheck). Отдельная команда вроде `uvicorn main:app ...` **ошибочна** (модуль — `app.main:app`) и даёт **второй** процесс на **8080** → `Address already in use`. Не добавляйте в команду запуска `alembic upgrade head` — миграции отдельно.

## Создание администратора (seed)

```bash
cd backend
python seed_admin.py
```

По умолчанию используются значения `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_DISPLAY_NAME` из `.env`.

## Продакшен (секреты и режим)

Файл `.env` с реальными секретами **не коммитьте** (в корне есть `.gitignore`). Выкладка опирается на переменные окружения хоста, CI/CD или секрет-хранилище.

**Обязательно:**

- `APP_ENV=production` — без этого не действуют жёсткие проверки секретов при старте.
- `DATABASE_URL` — явная строка подключения к рабочей БД; пустое значение в production приводит к ошибке при загрузке конфигурации.
- `SECRET_KEY` — случайная строка **не короче 32 символов**, не из списка плейсхолдеров (`change_me`, `replace_with_long_secret_key` и т.д.). Пример генерации: `openssl rand -base64 32`.
- `CORS_ORIGINS` — только доверенные URL фронтенда (через запятую).

**Рекомендуется:**

- Запуск `uvicorn` **без** `--reload`, без отладочного режима приложения.
- Пароли администратора (`ADMIN_PASSWORD` и т.д.) задать сильными при `seed_admin.py`, не копировать пример из `.env.example`.

Поведение для разработчиков **не меняется:** при `APP_ENV=development` по-прежнему можно поднять проект с SQLite по умолчанию и запасным JWT-секретом, если в `.env` нет сильного ключа (см. комментарии в `backend/app/config.py`).
